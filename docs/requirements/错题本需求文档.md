# WordBattle 错题本功能需求文档

**版本：** v1.1  
**日期：** 2026-08-03  
**状态：** 待评审

---

## 一、背景与目标

### 1.1 背景

当前 WordBattle 对战后，答错的单词没有后续跟踪。用户无法知道自己薄弱的词汇，也无法针对性地复习。同时设备为单用户模型，多人共用一台设备时无法区分各自的数据。

### 1.2 目标

- 支持多用户（每设备最多 5 个），各自拥有独立的错题数据
- 记录用户对战中的错题，形成个人错题本
- 通过星级体系标记薄弱环节严重程度
- 错题加权出题，让薄弱词更频繁地出现
- 提供赛后复盘、专项练习、统计查看三种回顾方式
- 支持拍照识别英语课本，快速导入自定义词库

### 1.3 范围

- 仅客户端本地功能，不跨设备同步
- 对战主机无需知道玩家的星级信息
- 对战排名使用用户名显示

## 二、功能五：多用户体系

### 2.1 用户名管理

**基本规则：**
- 每台设备最多 5 个用户名
- 至少保留 1 个用户（不能全部删除）
- 首页默认使用上一次登录的用户名，下次启动无需重新选择

**用户管理页面：**

```
┌─────────────────────────┐
│        用户管理           │
├─────────────────────────┤
│  ● 张三                  │
│    李四                  │
│    王五                  │
│  ──────────────────     │
│  + 添加用户（3/5）        │
└─────────────────────────┘
```

**CRUD 操作：**

| 操作 | 说明 |
|------|------|
| 添加 | 输入新用户名，不超过 5 个字符。名称不可重复 |
| 编辑 | 修改用户名。改名后，该用户所有历史数据（错题、wrong_count 等）跟随转移，数据归属不变 |
| 删除 | 左滑显示"删除"按钮。删除后该用户的错题数据一并清除。至少保留 1 个用户 |
| 切换 | 点击用户头像行切换当前用户，首页显示当前用户名 |

**入口：** 首页顶部显示当前用户名，点击进入用户管理页面。

### 2.2 对战中的用户名传递

**主机模式：**
- 从首页选择"当主机"，默认使用当前用户
- 加入房间时 `name=当前用户名`
- 排名显示 `用户名:5分`

**客户端模式：**
- 从首页选择"加入对战"，默认使用当前用户
- JOIN 消息 `name=当前用户名`
- 排名显示 `用户名:3分`

**同设备本地回环（主机+自己答题）：**
- 主机已选某用户，本地玩家默认使用同一用户
- 不同设备的玩家各自使用各自设备上的用户名

### 2.3 数据隔离

**核心原则：A 的错题和 B 的错题完全独立，互不影响。**

所有以用户为关联 key 的数据：

| 数据 | 隔离方式 |
|------|----------|
| 错题本星级 | 按用户名独立存储、独立计算 |
| wrong_count / last_wrong_time | 按用户名独立维护 |
| 加权出题 | 只使用当前用户的星级数据计算权重 |
| 赛后复盘 | 只展示当前用户的错题 |
| 单人练习 | 使用当前用户的错题本 |
| 错词统计面板 | 只展示当前用户的错词 |
| 对战排名 | 显示当前用户名 |

### 2.4 数据模型变更

错题存储增加 `username` 字段：

```
WrongWordEntry {
    username: String       // 所属用户
    word: String           // 英文单词
    star_level: int        // 0-6
    wrong_count: int       // 累计错误次数
    last_wrong_time: long  // Unix timestamp
}
```

所有错题查询加 `username` 条件。加权出题时也只遍历当前用户的星级数据。

### 2.5 数据初始化与迁移

- 首次安装：默认创建"玩家"用户名，所有词 star_level = 0
- 旧版本升级：现有错题数据归属默认用户
- 用户名改名：`UPDATE ... SET username = new_name WHERE username = old_name`，不影响数据归属

## 三、星级体系设计

### 3.1 星级定义

| 星级值 | 标记显示 | 含义 |
|--------|----------|------|
| 0 | 无 | 正常词，无错题标记 |
| 1 | ★ | 轻度薄弱 |
| 2 | ★★ | 中等薄弱 |
| 3 | ★★★ | 比较薄弱 |
| 4 | ★★★★ | 严重薄弱 |
| 5 | ★★★★★ | 极度薄弱 |
| 6 | ★★★★★+ | 最严重（五星上限后再错） |

### 3.2 星级变更规则

**答错时：**
- 当前星级 < 6：星级 + 1
- 当前星级 = 6：保持不变（已达上限）

**答对时：**
- 当前星级 > 0：星级 - 1
- 当前星级 = 0：保持不变

**"答对"的定义：** 该词作为题目词出现时，用户选择了正确答案。该词仅作为干扰选项出现时不计入。

### 3.3 持久化

- 错题数据存储在客户端本地（SQLite）
- 对战时不通过网络传输星级数据
- 每题结束后即时更新星级

## 四、功能一：加权出题

### 4.1 权重计算公式

```
weight = 2 ^ star_level
```

具体映射：

| star_level | weight |
|------------|--------|
| 0 | 1 |
| 1 | 2 |
| 2 | 4 |
| 3 | 8 |
| 4 | 16 |
| 5 | 32 |
| 6 | 64 |

### 4.2 出题流程

**步骤 1：计算权重**
- 遍历题库所有词，根据当前用户的 star_level 计算 weight
- 求所有词 weight 之和 total

**步骤 2：加权随机采样**
- 在 [0, total) 范围内生成随机数
- 按累积权重区间定位抽中的词
- 重复 N 次（N = 本局总题数）

**步骤 3：去重处理**
- 如果题库总词数 >= 2 × N：抽出的词尽量不重复，若抽到已出现过的词则重新抽取（最多重试 3 次，仍重复则保留）
- 如果题库总词数 < 2 × N：允许重复

**步骤 4：生成干扰项**
- 干扰项从题库中均匀随机抽取，不参与加权
- 干扰项与正确答案不重复

### 4.3 影响范围

- 对战模式出题
- 单人练习模式出题（不适用加权，见功能三）
- 不影响干扰项生成

## 五、功能二：赛后复盘

### 5.1 触发条件

一局对战结束后（收到 GAME_OVER 消息），自动进入复盘流程。

### 5.2 本轮错题记录

对战进行中，每题记录以下信息到本轮临时列表（关联当前用户）：

| 字段 | 说明 |
|------|------|
| word | 题目单词 |
| correct_answer | 正确答案文本 |
| user_answer | 用户选择的答案文本 |
| is_correct | 是否答对 |
| star_before | 答错前星级 |
| star_after | 答错后星级 |

### 5.3 复盘页面流程

**场景 A：有错题（本轮存在答错的题目）**

```
游戏结束页（排名，显示用户名）
       ↓
底部显示 "查看错题" 按钮
       ↓
点击 → 错题列表页
       ↓
[顶部] 本轮错题统计：X 题答对 / Y 题答错 / Z 题超时
       ↓
[列表] 每题一行：
  单词 | 正确答案 | 你的答案 | 星级变化（如 ★★→★★★）
       ↓
[底部] "练习这些词" 按钮（跳转单人练习，仅练本轮错题）
       │
       └── "返回主页" 按钮
```

**场景 B：全部答对**

```
游戏结束页（排名，显示用户名）
       ↓
底部显示 "全部答对，太厉害了！"
       ↓
无 "查看错题" 按钮
```

### 5.4 数据清理

- 本轮错题临时列表仅在本次对战结束后保留
- 用户离开复盘页面（返回主页或进入练习）后，临时列表清空
- 星级数据持久化保留，不受清理影响

## 六、功能三：单人练习模式

### 6.1 入口

主页新增"练错词"按钮。点击时进行判断（使用当前用户数据）：

- 错题本为空（当前用户无 star_level ≥ 1 的词）：弹窗提示"错题本为空，快去对战积累吧"
- 有错词：进入练习设置页

### 6.2 练习设置页

```
┌─────────────────────────┐
│       练错词设置         │
├─────────────────────────┤
│                         │
│  总题数                  │
│  ○ 5 题  ● 10 题 ○ 20 题 │
│                         │
│  星级筛选                │
│  ● 全部  ○ 3星及以上      │
│  ○ 5星及以上 ○ 五星加号    │
│                         │
│  ┌───────────────────┐  │
│  │     开始练习       │  │
│  └───────────────────┘  │
└─────────────────────────┘
```

### 6.3 练习出题规则

- 从符合条件的词池（当前用户满足星级筛选条件）中均匀随机抽取
- **不适用加权**（用户已经在错题池里，不需要再加权）
- 干扰项生成规则与对战一致

### 6.4 练习交互流程

```
┌─────────────────────────┐
│    单词                   │
│    [ 选项 A ]            │
│    [ 选项 B ]            │
│    [ 选项 C ]            │
│    [ 选项 D ]            │
│                          │
│    倒计时 ████████░░ 10s │
└─────────────────────────┘
         ↓ 选择后
┌─────────────────────────┐
│    单词                   │
│    [ 选项 A ✓ ]          │
│    [ 选项 B ✗ 你的选择 ] │
│    [ 选项 C ]            │
│    [ 选项 D ]            │
│                          │
│    答对！星级 ★★★→★★      │
│    （2秒后自动下一题）     │
└─────────────────────────┘
```

- 每题倒计时：10 秒（与对战一致）
- 答对/答错立即反馈，不等待超时
- 2 秒后自动进入下一题
- 星级按标准规则变更（答对 -1，答错 +1）

### 6.5 快速降星规则

为加速清理错题，练习模式下增加连续答对机制：

**计数器：`session_correct_streak`**
- 按单词独立维护，仅在当前练习会话内有效
- 每次该单词作为题目出现：
  - 答对：计数器 + 1
    - 计数器达到 3：该词 star_level 直接归零，计数器重置
  - 答错：计数器重置为 0

**示例：**
- 词 A 当前 4★，练习中出现 3 次都答对 → star_level = 0，该词移出错题本
- 词 A 当前 4★，练习中出现 2 次答对、第 3 次答错 → 计数器归零；星级变为 5★

### 6.6 练习结束页

```
┌─────────────────────────┐
│      练习完成             │
├─────────────────────────┤
│                         │
│    总题数：10            │
│    正确：8 题            │
│    正确率：80%           │
│                         │
│    星级变化：            │
│    3 个词降星            │
│    2 个词升星            │
│                         │
│  ┌───────────────────┐  │
│  │      再来一轮      │  │
│  └───────────────────┘  │
│  ┌───────────────────┐  │
│  │      返回主页      │  │
│  └───────────────────┘  │
└─────────────────────────┘
```

- 星级标记（★ 符号）
- 英文单词
- 错误次数

- 如果再次答错，星级从 0 重新开始上升

### 8.4 技术实现要点

**OCR 引擎：**
- Google ML Kit 离线文字识别
- 模型大小约 3MB，不依赖网络
- 印刷体识别准确率预期 95%+

**解析模板：**
- 每种课本类型对应一套预设解析规则
- 规则描述：如何从一行文本中提取 (word, meaning, correctIdx)
- 初始支持人教版、外研社两种常见版本
- "通用模板"适用于简单格式（如"单词 释义"）

**冲突处理：**
- 识别出的词与题库中已存在的词完全一致（单词 + 释义相同）→ 跳过
- 单词相同但释义不同 → 弹窗提示用户选择保留哪个
- 识别失败或无法解析的行 → 高亮标注，用户手动修正或删除

### 8.5 导入后的使用

- 导入的词进入当前用户的自定义题库
- 对战出题时，默认题库 + 自定义题库混合加权出题
- 支持在设置中查看/管理自定义词库（删除不需要的词）

### 8.6 限制与约束

- 每次最多连续拍 5 页
- 单次识别不超过 200 个词
- 需要相机权限
- 光线不足或拍摄角度过大时提示重新拍摄

## 九、数据模型总览

### 9.1 用户表

```
User {
    username: String    // 唯一，设备内不重复
    is_default: bool    // 是否为首选用户（首页默认登录）
}
```

### 9.2 错题表

```
WrongWordEntry {
    username: String    // 关联 User.username
    word: String        // 英文单词
    star_level: int     // 0-6
    wrong_count: int    // 累计错误次数
    last_wrong_time: long // Unix timestamp
}
```

### 9.3 自定义词库表

```
CustomWord {
    word: String        // 英文单词
    meaning: String     // 中文释义
    source: String      // 来源：课本类型 / 用户手动
}
```

## 十、非功能性需求

### 10.1 性能

- 加权出题计算应在 50ms 内完成
- 错题本页面加载应在 200ms 内完成
- OCR 单页识别应在 500ms 内完成
- 单机错题数量不设上限，但预期在 500 词以内

### 10.2 存储

- 错题数据占用不超过 1MB（预估 5000 词条 × 每条约 200 字节）
- OCR 模型增加约 3MB APK 体积

### 10.3 兼容性

- 旧版本升级后，所有词默认 star_level = 0
- 旧版本升级后，现有数据归属默认用户"玩家"
- 不对旧题库做迁移处理
