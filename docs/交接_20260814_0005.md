## 今晚的核心发现

### 1. 脚本后台运行导致 App 退到后台（根本原因）

- 脚本在后台执行时，MIUI 调度把 App 退到后台
- App 在后台时（`mResumed=false`），tap 事件**不产生任何日志**
- 手动 tap（App 在前台）则正常产生日志
- **monkey 也无法把 App 拉回前台**（`mCurrentFocus=null`）

### 2. MIUI 强制休眠屏幕

- `screen_off_timeout` 设置为 `2147483647`（最大值），但 MIUI 仍然强制休眠
- dumpsys power 显示 `mScreenOffTimeoutSetting=2147483647`，但实际 `mWakefulness=Asleep`
- MIUI 的休眠策略无视 system/secure 设置
- 用户已将休眠改为 10 分钟

### 3. Wake Lock 方案（未验证）

- HostGameScreen 中尝试添加 `FULL_WAKE_LOCK`，但编译后的 APK 没有 wake lock 记录
- 可能是 `FULL_WAKE_LOCK` 在 MIUI 上被忽略
- 回退了 wake lock 代码

### 4. UIAutomator dump OOM

- `adb shell uiautomator dump` 在扫描过程中被 SIGKILL（Exit 137）
- 脚本的 ANSWERING 检测依赖 uiautomator dump，可能因此失败

## 扫描逻辑

### HostGameScreen.kt 扫描模式

```kotlin
// Column 的 pointerInput 捕获所有点击
pointerInput(Unit) {
    detectTapGestures { offset ->
        DebugLog.i("[SCAN] bgTap y=${offset.y.toInt()}")
    }
}

// 按钮 onClick（只记录 idx）
DebugLog.i("[SCAN] onAnswer idx=$idx")
```

### 脚本判断逻辑

- `onAnswer idx=N` → Y 坐标命中按钮 N
- 只有 `bgTap` → Y 坐标在背景区域
- 两者同时出现 → 事件传播未阻断（旧版本 APK 问题）

### scan_buttons.py 流程

1. force-stop App → 安装 APK → 启动 App
2. tap 进入答题界面（4步 tap）
3. uiautomator dump 检测 ANSWERING 状态
4. 逐 Y 像素扫描（0~2400），tap 后等待 [SCAN] 日志
5. 分析按钮范围，输出中心坐标

## 未解决的问题

1. **脚本后台运行 → App 后台 → tap 无效**
   - 需要 App 保持在前台才能接收 tap 事件
   - monkey 拉不回来，`am start` 也不行

2. **MIUI 强制休眠**
   - 用户改为 10 分钟休眠，但如果扫描超过 10 分钟仍会失败
   - 2400 像素 × 每次 3 秒等待 = ~20 分钟（最坏情况）

3. **uiautomator dump 被 OOM kill**
   - 可能需要在脚本中重试或改用其他检测方法

---

## 可能的方向

1. 改用 `adb shell content query` 或 `logcat` 实时监听 `[SCAN]` 日志来检测 ANSWERING 状态，替代 uiautomator dump
2. 在扫描循环中插入唤醒+monkey 保持 App 前台（但要避免 tap 冲突）
3. 把脚本改为前台运行（PTY 模式），App 可能保持在前台
