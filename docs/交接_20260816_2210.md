## 核心机制（新 session 必读）

### 1. READY 握手（解决 25% 得分率的根因）
- 根因：App 固定节奏翻页，脚本慢链路 ADB tap 落地时屏幕已是下一题。
- 修法：GO 前脚本（observer）必须发 READY，App 收到才广播 GO。
  5 秒超时兜底（observer 不在线时照常开局）。**真人局无 observer，
  行为完全不变**（500ms 后 GO）。
- 代码位置：GameEngine.kt `startGame`（`hasObserver()` 分支）、
  `handleReady`；协议：GameMessage.kt `READY`。

### 2. observer 身份
- JOIN 带 `role="observer"`：不进 GameEngine.players → 不计分、不显示、
  不占答题名额、ANSWER 被 `players.containsKey` 拦截。
- TcpServer 维护 observers 集合，**断线自动清理**（防止残留 observer
  导致后续每局等 READY 5 秒超时）。
- 握手条件只看 observer 数量，与玩家名无关（早期"名字含 auto"的方案已废弃）。

### 3. 日志可靠性（5526779，真机使用关键）
- **推送熔断**：DebugLog 每条日志 HTTP POST 到工作站 192.168.50.201:8765
  （log_receiver.py）。旧代码失败时 `DebugLog.e()` 会再生成日志→再推送→
  滚雪球。现已修复：连续 10 次失败暂停 30 秒；失败提示走 `localNote()`
  只写本地文件。
- **文件轮转**：本地日志 10MB 滚动（.current/.old 两份）。
- **Debug 页开关**：长按标题 5 次进 Debug 页，可开/关推送、看状态。
- ⚠️ 服务器 IP 硬编码 `192.168.50.201`（DebugLog.kt:26），换工作站要改代码。

## 自动化测试体系（scripts/）

```bash
# 标准用法（参数全部可配）
python3 scripts/auto_test.py --rounds 20 --seconds 10
# --rounds {5,10,20,30}  --seconds {5,10,20,30,120}  --mode {all_correct|random}
# --device b054d001  --ip 192.168.50.187
```

- 流程：force-stop → 主机设置 → 设题数/秒数（标签锚定定位）→ 开始等待
  → **TCP 连 App（observer）→ 收 GO 读 correctIdx → ADB 真按钮 tap**
  → 结果页 → force-stop → **息屏（KEYCODE_SLEEP 223）**。
- 铁律：必须 ADB tap 模拟真实点击，**禁止 TCP 直发 ANSWER**。
- 验证记录：30/30（5秒）、10/10（10秒）、20/20（10秒）、10/10（5秒，
  新日志版）——全部满分，每题"屏幕=GO 一致"。
- `scripts/dump_setup.py`：设置页布局诊断（含 MIUI 浮不起重试）。
- `scripts/tests/`：3 个本地单测（wait_for 删除语义/并发安全/按钮定位）。
- 已知坑（已修）：wait_for 必须快照迭代+命中即删（deque 并发竞态）。
