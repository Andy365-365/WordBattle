# 测试纪律（每次在真机上操作前必读）

> 适用范围：所有在测试机（小米 Redmi K20 Pro, b054d001）上进行的安装、UI 操作、自动答题、日志抓取工作。
> 本文件由 agent 在开始任何 WordBattle 真机测试前加载并逐条执行，收尾时逐条核对。

## 1. 屏幕纪律（2026-08-16 起因）
- 测试开始前记录当前状态：`adb shell dumpsys power | grep mWakefulness`、`adb shell settings get secure screen_off_timeout`。
- 跑自动答题/坐标扫描期间，允许临时 `adb shell settings put secure screen_off_timeout 2147483647`（永不熄屏，Doze 会杀掉 HTTP 推送）。
- **测试结束后必须**：
  1. `adb shell settings put secure screen_off_timeout 600000`（恢复 10 分钟）
  2. `adb shell input keyevent KEYCODE_POWER` 息屏
  3. `adb shell dumpsys power | grep mWakefulness` 确认 `Asleep`
- 整夜亮屏会耗尽测试机电量，这是用户明确指出的问题。

## 2. 日志纪律
- 分析前确认 VERSION 和时间戳匹配当前 APK。
- 两条异步流（设备端/网络端）按 round 字段对齐，不按行序对齐。
- log_receiver 用 socket 连接验证存活，不用 pgrep。
- 截断日志文件必须原地 truncate，禁止删除（会破坏 log_receiver 的文件句柄）。

## 3. 构建纪律
- **一律用 `bash scripts/build.sh` 编译**（自动写新版本号 + clean + assembleDebug）。禁止手动敲 gradle 命令——手动编译必然漏更新 VERSION，用户已因此批评过（2026-08-17）。
- 版本号格式：v[大版本]-[YYYYMMDD]-[HHMM]（DebugLog.kt，build.sh 自动生成）。
- 改 .kt 后必须 clean 构建（build.sh 已内置），防 UP-TO-DATE 旧 APK。
- 装完必须验证版本号生效：启动 App，grep 当日日志确认新 VERSION 出现在运行日志里（文件 grep 不算数，App 必须真实跑起来）。

## 4. 验证纪律
- UI 改动：uiautomator dump 拿 bounds 坐标验证（不靠 LLM 看截图猜坐标）。
- 出题逻辑：从主机日志抓 GO 消息 JSON 验证实际下发内容，不靠界面截图。
- 修复必须真机实测通过才算完成，向用户汇报时附实测证据。

## 5. 编码纪律
- 改动时遇到的**现有代码/选项**若本身可疑（不合理、来源不明、与产品语义冲突），先停下质疑并问用户，不得"顺从现状"直接适配。
  - 起因：2026-08-16 布局修复时，等待时间行有个 120s 选项（实为坐标扫描调试遗留），agent 未质疑直接适配，被用户指出"没让你加，也不合理"，已删除。

## 6. 答题与轮次机制（勿破坏）
- **必须用 ADB tap 触发答题，禁止 TCP 直发 ANSWER 消息**——自动化测试的意义就是验证真实输入链路。
- 节奏保障靠 READY 握手：有观察者（脚本以 `JOIN role=observer` 身份加入，不计分不显示，服务器断线时清理）在场时，主机 `nextRound` 等观察者 READY 后才广播 GO（超时 5s 照常发，防卡死）；无观察者的真人对局保持 500ms 原节奏。
- 历史教训：固定 sleep 对齐 5s 翻页永远失败（tap 慢链路与翻页节奏错位，25% 巧合命中），2026-08-16 已用握手解决，30 题两轮 30/30。详细过程见《交接-自动化测试-tap-round问题.md》。
