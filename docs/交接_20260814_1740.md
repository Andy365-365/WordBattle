## 2. 技术架构

### 整体结构
```
app/src/main/java/com/wordbattle/
├── MainActivity.kt              # 入口，Compose 主题
├── data/
│   ├── Word.kt                  # 单词数据模型
│   ├── WordRepository.kt        # 单词库（SQLite）
│   └── UserRepository.kt        # 用户管理
├── game/
│   ├── GameEngine.kt            # 游戏主逻辑：出题、计时、打分
│   └── ScoreBoard.kt            # 排行榜
├── network/
│   ├── GameMessage.kt           # 消息定义（Serialization data class）
│   ├── TcpCodec.kt              # JSON 编解码（4字节长度前缀）
│   ├── TcpServer.kt             # 主机端 TCP 服务
│   ├── TcpClient.kt             # 客户端 TCP 连接
│   └── UdpDiscovery.kt          # UDP 广播发现主机
├── ui/
│   ├── Screen.kt                # 导航枚举
│   ├── HomeScreen.kt            # 首页（主机/加入）
│   ├── HostSetupScreen.kt       # 设置页（题目数、答题时间）
│   ├── HostWaitingScreen.kt     # 等待玩家
│   ├── HostGameScreen.kt        # 主机游戏界面
│   ├── PlayerGameScreen.kt      # 玩家游戏界面
│   ├── PlayerJoinScreen.kt      # 加入房间
│   ├── ResultScreen.kt          # 结果页
│   ├── DebugScreen.kt           # 调试页（连按5次标题）
│   ├── UserManageScreen.kt      # 用户管理
│   └── OcrTestScreen.kt         # OCR 测试
└── debug/
    ├── CrashHandler.kt           # 崩溃捕获
    └── DebugLog.kt               # 调试日志（带版本标记）
```

### 网络协议
JSON over TCP（4字节长度前缀）+ UDP 广播发现

| 消息 | 方向 | 说明 |
|------|------|------|
| ADVERTISE | Host→UDP | 主机广播 |
| JOIN | Client→Host | 玩家加入 |
| WELCOME | Host→Client | 分配玩家ID |
| PREPARE | Host→Broadcast | 准备下一题 |
| GO | Host→Broadcast | 发送题目（**含 correctIdx**） |
| ANSWER | Client→Host | 提交答案 |
| REVEAL | Host→Broadcast | 揭晓答案 |
| SCORE | Host→Broadcast | 更新比分 |
| GAMEOVER | Host→Broadcast | 游戏结束 |

### 两个 Product Flavor
- **host** (`com.wordbattle`)：英语抢答-主机
- **client** (`com.wordbattle.client`)：英语抢答-客户端（共存）

## 3. 构建与测试流程

### 构建

```bash
cd /data/wordbattle

# 一键构建（build.sh 自动设置环境变量+版本号）
bash scripts/build.sh

# 产物
app/build/outputs/apk/host/debug/app-host-debug.apk
app/build/outputs/apk/client/debug/app-client-debug.apk
```

**版本号格式**：`v2.0-20260814-1518`（由 `build.sh` 写入 `DebugLog.kt`，格式 `YYMMDD-HHMM`）

**重要**：代码变更后如果 Gradle 报 UP-TO-DATE，必须先 `clean` 再构建。

### 安装

```bash
python3 scripts/auto_install.py
```
自动处理 MIUI 的 10 秒安装确认框（轮询检测，delay 0.5s）。

### 日志接收

```bash
# 启动
python3 scripts/log_receiver.py
# 监听端口：8765
# 日志写入：logs/remote_all_YYYYMMDD.log
```

### 自动化测试

```bash
python3 scripts/auto_test.py
```

**功能**：
- 自动唤醒屏幕 → 启动 App → 设置 30 题 → 设置答题时间 → 开始游戏
- 日志驱动答题：解析 GO 消息获取 `correctIdx`，选择对应坐标
- 三种模式：`all_correct`（全对）、`all_wrong`（全错）、`random`（随机）
- 坐标：(540,770), (540,946), (540,1122), (540,1298) — 经 UI dump 确认

**当前状态**：
- correctIdx 匹配已稳定（几乎 100% 匹配成功）
- ANSWER 发送率约 70-80%（部分轮次因脚本处理开销在 REVEAL 之后才 tap）
- 脚本从"广播 GO"到 tap 的处理链：`consume_line("广播 GO")` → `feed_pending` → `consume_line(GO JSON)` → `tap`
- 已确认根因：`feed_pending` 覆盖 pending 缓冲区，导致 `consume_line` 可能匹配到旧轮次

### 坐标扫描

```bash
python3 scripts/scan_buttons.py
```
通过 1px swipe 扫描 + UI dump 确认按钮坐标，防 MIUI 后台休眠。
