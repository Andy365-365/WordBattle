## 扫描原理

### 日志通道
- `DebugLog.i()` 通过 HTTP POST 推送到 log_receiver（端口 8765）
- log_receiver 按天写入日志文件：`/data/wordbattle/logs/remote_all_YYYYMMDD.log`
- 脚本直接读日志文件，不读 logcat

### tap_and_wait 同步逻辑
1. `tap(540, y)`
2. 轮询日志文件，读取最后几行
3. 匹配到新的 `[SCAN]` 行 → 解析 `onAnswer idx=N`（命中按钮）或 `bgTap y=...`（背景）
4. 3 秒超时 → 返回 None

### 阶段1：全屏幕扫描
- Y 从 0 到 2400，1px 步进
- 不提前终止，扫满 2400
- 记录每个按钮的首次命中 Y

### 阶段2：边界扩展
- 对每个按钮，从首次命中 Y 向上/向下 1px 扩展
- 直到碰到非该 idx 的结果（bgTap 或其他 idx）
- 确定上下边界后计算中心坐标

### 2400 条日志的保证
- 每次 tap 都会触发 onAnswer 或 bgTap，日志文件中应该有 2400+ 条 `[SCAN]` 行
- "重新开始"按钮在底部 Y=2250+，tap 到它不会输出 `[SCAN]` 日志，返回超时 None，不影响扫描
